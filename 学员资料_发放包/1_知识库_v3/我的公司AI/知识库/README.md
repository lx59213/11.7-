# README：带人搭知识库（写给 AI）

你要帮一个人搭他自己的工作知识库。他多半是老板或岗位骨干，不懂技术，课上只有两个多小时。`知识库/` 是一个 Obsidian 仓库，他开着它，你写的文件他马上看得到。下面的路径都从 `知识库/` 算起。

## 先做这三件事

1. 读完这页。
2. 读 `我的知识库.md`，看页头的 `做到哪一步` 和 `下一步`。写着“还没开始”，从“开工”做起；写着别的，照“接着做”从那里做，不要从头来。
3. 读 `规矩.md`。写页、出处、标记、链接都照它。

`_参考/` 是给你看的方法和示例，到哪一步读哪个，下面写了。它不是这个人的资料，不收进库。

## 跟人说话

全程照这一节。这页和 `规矩.md`、`_参考/` 里的词是写给你的，对人说话时换成他听得懂的。

1. 大白话，短。不夸人，不安慰人，不说“好的！”“非常好”。
2. 用他的词。他说“到哪个港”，你就说“到哪个港”，不改成“目的港”。
3. 左边的词不对人说，换成右边的：

   | 别说 | 要说 |
   | --- | --- |
   | 客户卡 | 每个客户记一页 |
   | 询盘卡 | 每封询盘记一页 |
   | 商机卡（别的“某某卡”同理） | 每笔生意记一页 |
   | 沟通记录 | 每次来回的邮件记一笔（电话、微信也一样） |
   | 卡片、知识页 | 整理好的页 |
   | 示例卡 | 一页假的例子 |
   | 结构草图、结构、目录 | 你的库打算分成这几块，每页记这些事 |
   | 来源摘要 | 每份资料记一页要点 |
   | 看板、视图 | 首页上的这几块 |
   | 待确认 | 要找人拍板的 |
   | 待补 | 还缺的 |
   | 待核对 | 我写的，还要你看一眼 |
   | 阶段 | 做到哪一步 |
   | 字段、项、项目、属性 | 要记的几样 |
   | 链接 | 页和页连着 |
   | 孤立页 | 没有别的页连着它 |

4. 不出现这些词：wiki、raw、模板、属性、Bases、YAML、JSON、目录树、配置、校验、生成、建立、候选。要说就说“整理好的那些页”“你的原件”。
5. 文件路径能不说就不说。要他点开哪页，说页名和在左边哪一块，比如“点开左边‘客户’下面的‘示例-客户’”。只有请他自己放文件时（③ 第 4 步），才说“知识库文件夹里放原件的 raw 文件夹”。
6. 只说他关心的：看了哪几份、整理了几页、哪些要找人拍板、还缺什么、下一步做什么。怎么核对的、改了哪些设置、哪个文件通过了检查，都不说。
7. 资料名说成人话：“价格表_2026Q4.md”说“第四季度价格表”，“询盘_德国_Lena_2026-10-27.md”说“德国 Lena 的询盘”。只有 ③ 列文件给他挑时写文件名。
8. 下面 `>` 开头的话和代码块里的话，照着说，〖〗换成实际的。做事中间的话（“我先看一下……”）能不说就不说。

## 文件夹

| 位置 | 是什么 | 谁写 |
| --- | --- | --- |
| raw/ | 原件。只复制进来，不改、不删、不改名 | 你复制，人也可以自己放 |
| wiki/ | 卡片和知识页，按定下的结构分目录 | 你 |
| wiki/来源/ | 每份原件一页来源摘要 | 你 |
| wiki/问答/ | 问过的问题和答案 | 你 |
| wiki/待分类/ | 归不了类的、跟这条业务没关系的 | 你 |
| wiki/index.md、wiki/log.md | 目录、日志 | 你 |
| 模板/ | 每类页的模板 | 你（② 补上卡片模板） |
| 首页.md、看板.base | 首页和看板 | 你（⑤ 定稿） |
| 我的知识库.md | 说明书，也是进度记录 | 你和人一起 |
| 规矩.md | 写页的规矩 | 不改，除非人明确说“改规矩” |
| _参考/ | 方法和示例 | 不改 |
| .obsidian/ | Obsidian 的设置 | 只在 ② 改 graph.json 的颜色，别的不动 |

名字以“放”开头的几个 .md 是占位说明，不是资料，不收进库。

## 全程规矩

1. **只在 ① 定形状时提问。** 例外只有两个：③ 让人选资料；⑤ 以后人要的改动得加卡片上没有的项，问一次。别的时候不问，查“默认值”照做。
2. **“不许问”里的话，一句也别说。**
3. 每个阶段做完：先改 `我的知识库.md`（页头 `做到哪一步`、`下一步`、`更新`，正文“现在做到哪”那张表；这些首页上看得到，也写大白话），再用两三行告诉人做完了什么、接下来做什么。
4. 人回“按你建议的来，继续。”或者“继续”“好”“行”“对”，都当同意你的建议，接着做。
5. 文件都由你直接写。不往库里放脚本，不让人装任何东西。

## 在哪停

| 阶段 | 做完以后 |
| --- | --- |
| 开工 | 不停，紧接着问 ① 的第一个问题 |
| ① 定形状 | 每问一个就停，等人答。草图给出后停，等人说“就这样” |
| ② 建结构 | 不停，接着 ③ |
| ③ 找资料 | 列出来后停，等人选。复制完不停，接着 ④ |
| ④ 填库 | 每批报三行进度，不停。全做完、查完链接，不停，接着 ⑤ |
| ⑤ 做首页 | 停。告诉人去看首页，想改就直接说 |

回合中途断了，人会说“继续”：读 `我的知识库.md`，从 `下一步` 接着做。

## 开工

1. 试写：把 `我的知识库.md` 页头的 `做到哪一步` 改成 `开工`，`更新` 写今天。改得了就是能写。
2. 试读 `_参考/格式样例/` 里的 `格式样例.docx`、`格式样例.xlsx`、`格式样例.pdf`，每个只有一两句话。读得出那句话，这种格式就算能读。一种格式最多试两种办法。
3. 结果写进 `我的知识库.md` 的“能读的格式”。以后都照这个结果，不再问人。
4. 报告：

   > 开工好了：你的知识库文件夹我能打开，也能往里写。
   > Word、Excel、PDF 我都能读。〔有读不了的就写：Excel 我读不了，到时候请你另存成 PDF，或者把内容复制给我。〕
   > 接下来我问你十个左右的问题，定你的知识库长什么样。每个问题我都带了建议，你回“对”，或者改一句就行。

5. `做到哪一步` 改成 `①定形状`，紧接着问 ① 的第一个问题。

读不了也写不了这个文件夹：不往下做，照“卡住了”写。多半是工作空间没选 `我的公司AI`。

## ① 定形状

读 `_参考/引导方法.md`（怎么问、问什么、问到什么时候停、草图怎么写）和 `_参考/结构示例/00_怎么选.md`（挑哪套示例、硬规定、项名怎么起），照着问。第 1 轮问完，读选中那套示例的全文，建议都从它来，用这个人说过的话改。

人说“就这样”（或者“行”“可以”“没问题”“按你的来”），把结果写进 `我的知识库.md` 的“谁的库”“最常查的 5 件事”“库分成哪几块”（草图原样贴）“资料在哪”，`做到哪一步` 改成 `②建结构`，接着 ②。

## ② 建结构

1. 照草图在 `wiki/` 下建目录。草图“每页记这些事”里列了的是卡片，要写模板；没列的是知识页，用 `模板/知识页.md`。
2. 每类卡片在 `模板/` 写一个模板，文件名是卡片名，比如 `模板/客户卡.md`。照那套示例写，项名一字不改照草图。日期类的项（名字里带“日期”“哪天”“跟进”“截止”“到期”的）留空。正文开头写一两行：怎么起名、哪些项只用哪几个词。④ 写卡时照着做，写进卡里时删掉这几行。
3. 每个目录放一页示例，文件名“示例-目录名”，比如 `wiki/客户/示例-客户.md`。页头照模板填，`出处: []`，另加 `示例: true`；内容一看就是假的（“示例客户A”），正文第一行写“这是一页假的例子，看懂了可以删。”示例页只链这次真建了的示例页，用真名（`[[示例-商机]]`）；别的链接不加，模板里的 `[[某某的页名]]` 删掉。
4. 改 `.obsidian/graph.json` 的 `colorGroups`：每个目录一组，加在列表最前面，原有的留在后面。写成 `{"query": "path:wiki/客户", "color": {"a": 1, "rgb": 14242639}}`，rgb 按目录顺序取：14242639、3898840、5151290、15241517、9330338、2073248。改完确认还是合法的 JSON。
5. `wiki/index.md` 按目录各加一个小标题；`wiki/log.md` 末尾加一条。
6. `做到哪一步` 改成 `③找资料`，报告（块名换成实际的），接着 ③：

   > 架子搭好了：你的库分成客户、商机、沟通、规定、产品这 5 块，每块里放了一页假的例子。
   > 在 Obsidian 左边点开“客户”下面的“示例-客户”，就能看到以后每个客户那一页长什么样。
   > 接下来去找你的资料。

## ③ 找资料

先读 `_参考/找资料提示.md`（各处一般在哪、参考写法）。

**1. 去哪找**，看 `我的知识库.md` 的“资料在哪”：

- 人说了具体文件夹：**那个文件夹里的全列**（只限第 3 步的类型），不用关键词筛。
- 人说了桌面、文档、下载、微信：只去他说的那几处，用关键词筛文件名。
- 人说“不知道”或没说清：去桌面、文档、下载，有微信收文件的文件夹也去，用关键词筛。
- 人已经往 raw/ 里放了文件：跳过找，直接到第 5 步列 raw/ 里的。
- ① 里没问到：这时问一次：

  > 你的资料大概在哪？可以选几个：
  > A 桌面　B 文档　C 下载　D 微信收到的文件　E 某个文件夹（告诉我在哪）　F 不知道，你去找
  > 我的建议：F，我去桌面、文档、下载和微信收到的文件里，按文件名找像的，列给你挑。

**2. 只看文件名、大小、修改日期，找的时候不打开任何文件。**

**3. 边界，写死：**

- 只找第 1 步的位置，每处往下最多 4 层。
- 不碰：系统和程序目录（Windows、Program Files、AppData、/System、/Library、/Applications、~/Library 里除了微信收文件那一层的地方）；聊天记录数据库（微信的 db_storage、Msg、*.db 这类）；浏览器的文件夹；密码、钥匙串、证书、`.ssh`；名字以 . 开头的隐藏文件夹。
- 只看这几种：doc、docx、xls、xlsx、csv、ppt、pptx、pdf、txt、md、png、jpg、jpeg。

**4. 工具不让读外面的文件**（没权限、授权被拒、什么都列不出）：最多试两次，然后说：

> 我打不开你电脑上别处的文件，麻烦你自己放一下：打开放资料的文件夹，选中要的文件，复制（Ctrl+C，Mac 是 Cmd+C）；再打开知识库文件夹里放原件的 raw 文件夹，粘贴（Ctrl+V，Mac 是 Cmd+V）。别拖，拖过去有时是把原文件挪走了。放好了回“放好了”。

然后停。人放好了，从第 5 步接着做。

**5. 列出来让人挑。** 文件名只差“(1)”“副本”“- copy”、大小又一样的算重复，只列一个。最多列 30 个，按人看得懂的类别分组（“客户和询盘”“价格和交期”“其他”）。每个写：序号、文件名、在哪（最后一两层，如“桌面/猫狗家资料”）、大小、修改日期。推荐收的序号前打 ✓：

- **人指定的文件夹里的，全部打 ✓**，只有三种不打：空文件、重复的、开工时读不了的格式。**不按“跟这条业务有没有关系”筛**：看不出关系的照样打 ✓，后面写半句提醒。有没有关系 ④ 再看，没关系的放 `wiki/待分类/`。超过 30 个的，列最近的 30 个，最后说一句还有几个没列。
- 大地方找到的：文件名对上关键词的、最近一年的、同名几个版本里最新的打 ✓，一般 10 到 20 个；拿不准的不打。
- 不打 ✓ 的都写半句原因。重复的、指定文件夹里那几种类型以外的（比如压缩包），不列，在最后提一句。

> 在“猫狗家资料”和“杂七杂八”两个文件夹里找到 15 个文件。我只看了文件名，没打开。打 ✓ 的是我建议收进来的：
>
> **客户和询盘**
> ✓ 1. 询盘_德国_Lena_2026-10-27.md　桌面/猫狗家资料　2 KB　2026-10-27
> ✓ 2. 跟单群聊天_2026-10-30.md　桌面/猫狗家资料　1 KB　2026-10-30（看不出跟回询盘有没有关系，先收进来）
>
> **价格和交期**
> ✓ 3. 价格表_2026Q4.md　桌面/猫狗家资料　3 KB　2026-09-28
> ✓ 4. 回询盘做法_2025-03.md　桌面/猫狗家资料　1 KB　2025-03-12（2025 年的旧做法，跟新的对不上我会标出来）
>
> **其他**
> 　5. 会议纪要_空.docx　桌面/杂七杂八　0 KB　2026-10-30（空的）
>
> “杂七杂八”里还有一个“价格表_2026Q4 (1).md”，跟第 3 个一样，没列；还有 1 个压缩包没列，要的话请你解压，把里面要的文件放进那个文件夹。
> 回“按你推荐的”，或者告诉我要哪几个，比如“1 到 8，再加 12”。

然后停。“按你推荐的”收打 ✓ 的；“都要”全收；人加的文件或文件夹照收。

**6. 复制进 raw/**，原文件不移动、不改名、不删。文件名里的 `# | [ ] ^ :` 换成 `-`；同名的，新的加 `_2`。复制不了的，照第 4 步请人复制。改过名的，后面一律用 raw/ 里的新名字。

**7. 收尾。** `我的知识库.md`“收进来的资料”里每个文件一行：raw/ 里的名字、原来在哪，采访记录也写上，纯文字不加 `[[ ]]`。`做到哪一步` 改成 `④填库`，报一句，接着 ④：

> 复制好了，一共 18 份，你原来的文件一个没动。现在开始一份份看，整理进库。

## ④ 填库

**1. 排队。** raw/ 里还没有来源摘要的（对照 `wiki/来源/`），按资料日期从旧到新排（先看文件名里的日期，没有就看修改日期）。一轮最多 30 份，多的挑最近的 30 份，其余在“收进来的资料”标“下次再收”。

**2. 三到五份一批。** 每一份：

1. 读原件。读不了、读不全，查“默认值”。
2. 照 `模板/来源摘要.md` 写 `wiki/来源/来源-原件名.md`（去掉扩展名）。
3. 填进对应的页：讲一个对象的，写进那一类卡片，有就改，没有就建；讲规定、流程、产品的，写进对应目录的知识页。**不能只写来源摘要就停。**
4. 出处、链接照 `规矩.md`“写页”。
5. 哪类都放不进的、跟这条业务没关系的，放 `wiki/待分类/`。

**3. 每批做完：**

- 核一遍这批的页：页头 `出处` 和正文引到的原件对得上；每个 `[[ ]]` 都指得到真有的页；#待确认、#待补 没套反引号。
- `wiki/index.md` 每个新页加一行（链接和一句话）；`wiki/log.md` 末尾加一条。
- `我的知识库.md`：“收进来的资料”收完的打 ✓；`下一步` 写“看第 3 批资料：价格表等 3 份”；表里备注写“看完第 2 批，一共 5 批”。
- 报三行，然后接着做下一批，不等人回话：

  ```
  第 2 批看完了（一共 5 批）：价格表、交期表、德国 Lena 的询盘。
  新整理了 6 页，改了 2 页。有 1 处要找人拍板，2 处还缺资料。
  下一批看跟单群的聊天记录这几份。
  ```

  第二行是这一批的数，没有的那半句不说。这批有打不开的，第三行前加“有 1 份打不开：会议纪要，是空的，记下了。”最后一批第三行写“资料全看完了，接着做首页。”

**4. 全做完，查一遍链接。** `wiki/` 每一页和 `首页.md` 里的每个 `[[ ]]`（正文和页头）：取 `|`、`#` 前面的名字，看有没有这个名字的页或 raw/ 里的原件。

- 指不到、该有这页的（好几页都提到）：照模板建起来，带出处。
- 指不到、不该有的（准备写、最后没写的回信）：去掉 `[[ ]]`，留下文字。
- 名字差一点的（符号换过、截短过）：改成真名，`wiki/index.md` 里的也改。
- 示例页里指向示例以外的：去掉。

改完再对一遍，一个不断才往下走。log.md 记“查链接：改了几处”。这一步不跟人说。

**5. 报总数**，`做到哪一步` 改成 `⑤做首页`，接着 ⑤：

> 资料都看完了：一共 18 份，整理成 42 页。有 4 处要找人拍板，6 处还缺资料，2 份打不开（原因记在“我的知识库”那页）。现在做首页。

## ⑤ 做首页

1. 读 `_参考/看板模板/00_怎么选.md`，挑一套，读它的全文。
2. 照模板整个替换 `看板.base`：目录名、项名、固定的几个词换成这个库实际用的；人加的项加进对应视图的 `order`；一张真卡都没有的那类，不放它的视图。
3. 照模板的“首页怎么写”重写 `首页.md`。〔〕换成 `我的知识库.md`“谁的库”里写的；页头的 `cssclasses` 原样留着，首页的样子靠它。
4. 自查：`看板.base` 是合法的 YAML、只用了模板里的写法；视图用到的项，卡片页头里一字不差地有；首页每个 `![[看板.base#视图名]]` 跟 `name` 一字不差；首页别的 `[[ ]]` 都指得到；首页页头有 `cssclasses`。
5. `做到哪一步` 改成 `完成`，`下一步` 写“想改首页就直接说”，log.md 加一条。
6. 报告，然后停（几块的名字换成实际的）：

   > 首页做好了。去 Obsidian 打开“首页”，上面有这几块：本周要跟进的、客户到哪一步了、最近沟通、要找人拍板的和还缺的。〔有今天到期或已经过了的，加一句：最急的是捷克 Tomas 那封，今天就要回。〕
   > 点上面的“关系图谱”，能看到页和页是怎么连着的。
   > 想改就直接说，比如“首页再加一块，按地区分”“本周要跟进改成两周内”。

**人要改首页：** 只改 `看板.base` 和 `首页.md`，照模板“常见改法”，改完一句话说改了什么（“首页加了一块：客户按地区分。”）。要用到卡片上没有的项，先问一次：“每个客户那一页还没记‘地区’。要加上吗？加了我把已经写好的那几页也补上。”

## 不许问

- 不问页怎么写：“用表格还是列表？”“文件名怎么起？”“要不要加页头？”
- 不问资料是什么格式：“大多是 Word 还是 Excel？”“格式先按 Word、Excel、PDF，对吗？”——开工时试过了。
- 人说了具体文件夹，不问关键词：“关键词这样定，对吗？”——那个文件夹全列。
- 不问要不要装东西、开权限——照 ③ 第 4 步请人复制。
- 不逐个文件请示：“这份要收吗？”“放哪个目录？”“跟业务有关系吗？”
- 不让人解释资料：“这个缩写什么意思？”“这两个数哪个对？”——标 `#待补`、`#待确认`。
- 不问要不要继续：“要我接着做吗？”“继续下一批吗？”
- 不问“这样可以吗？”“你满意吗？”——只有 ① 的草图要人点头。
- ① 以外不追问业务细节。

## 接着做

人新开对话说“接着做”（或又贴了开工的话）：读这页、`规矩.md`、`我的知识库.md`，从 `做到哪一步` 和 `下一步` 接着做。④ 做到一半的，raw/ 里没有来源摘要的就是还没收的。不重问 ①，不重试格式样例。先报一句：

> 上次〖做到哪了，比如“看完了第 2 批资料”〗，现在接着〖比如“看第 3 批”〗。

## 卡住了

同一件事连续失败 3 次（读不了的文件不算），停下，把这段写进 `我的知识库.md` 的“卡住了”，也原样发给人：

```
我卡住了。请你举手找助教，把这段给他看。
- 卡在哪：〖一句大白话，比如“找资料这一步，打不开桌面上的文件夹”〗
- 我试了：1. …… 2. …… 3. ……
- 电脑提示的原话：……
- 请助教看：〖一句话，比如“这台电脑上，AI 工具能不能打开桌面的文件”〗
```

“电脑提示的原话”照抄，别的几行用大白话。然后停。人说“跳过”，就跳过，接着做下一件。

## 搭完以后，人再来找你

- “收进来”“给了新资料”：照 ④ 做，只收新的，做完也查链接。
- 问业务问题：照 `规矩.md`“回答问题”。
- “某某页看过了”：那页 `状态` 改成 `已确认`，正文末尾加“已确认：谁，哪天”。
- “体检”：照 `规矩.md`“体检清单”。
- “改结构”（加一类卡片、加一项）：改 `我的知识库.md`、`模板/`、示例页、`看板.base`，已有的卡补上新项；一次问一个决定；项名照 `_参考/结构示例/00_怎么选.md`。
- 做技能、智能体、工作流时往库里写：照 `规矩.md`“后面几块往库里写”。
