# 结构示例：人事招聘

**先说隐私**：候选人和员工只写代号（“候选人A”“销售部小王”），不写手机号、身份证号、工资实数。真实信息留在原件里，原件也先换代号，并确认公司允许放进所用的工具。

## 分成哪几块

```
wiki/
├─ 岗位/     每个岗位记一页
├─ 候选人/   每个候选人记一页（只写代号）
└─ 制度/     考勤、假期、薪酬、入职离职这些制度和流程，一条一页
```

## 岗位卡（`模板/岗位卡.md`，放 `wiki/岗位/`）

起名：部门-岗位，比如 `销售部-外贸业务员`。

```markdown
---
类型: 岗位
状态: 待核对
更新: "{{date}}"
出处:
  - "[[raw/文件名.扩展名]]"
部门:
要招几人:
还招不招:
负责人:
最要紧的事:
---
# {{title}}

## 做什么

- 职责、汇报给谁。（出处）

## 要什么样的人

- 硬条件、加分项、不要的。（出处）

## 候选人

- [[候选人卡的页名]]：到哪一步了。

## 待补

- 没有就写“无”。
```

各项怎么填：

- 要招几人：数字。
- 还招不招：只用“在招”“先停”“招满了”。
- 负责人：用人部门谁拍板。

## 候选人卡（`模板/候选人卡.md`，放 `wiki/候选人/`）

起名：代号-岗位，比如 `候选人A-外贸业务员`。

```markdown
---
类型: 候选人
状态: 待核对
更新: "{{date}}"
出处:
  - "[[raw/文件名.扩展名]]"
岗位:
做到哪一步:
从哪来的:
下次跟进:
最要紧的事:
---
# {{title}}

应聘：[[岗位卡的页名]]

## 情况

- 经历要点，只写跟岗位有关的。（出处）

## 面试记录

- 哪天、谁面的、怎么看。

## 待补

- 没有就写“无”。
```

各项怎么填：

- 岗位：写成 `"[[岗位卡的页名]]"`。
- 做到哪一步：只用“看简历”“约面试”“面过了”“发了录用通知”“入职了”“没通过”。
- 从哪来的：招聘网站、内推、猎头……
- 下次跟进：下次联系或面试的日期。

## 制度（知识页）

照 `模板/知识页.md` 写，放 `wiki/制度/`，`类型` 写“制度”或“流程”。比如 考勤规定、年假怎么算、入职要交的材料、离职流程。员工常问的写清楚“从哪天起”。

## 首页上放什么

- 在招的岗位。
- 候选人到哪一步了。
- 本周要跟进的候选人。
- 最近改过的制度；要找人拍板的和还缺的、还没整理的原件。

## 定形状时常问

1. 问：你天天打交道的是哪几样？
   建议：岗位、候选人；另外是考勤、假期、薪酬这些制度。
2. 问：最常查、最常被问的 5 件事？
   建议：年假怎么算、加班怎么算、入职要交什么、某个岗位招到哪一步了、离职怎么办手续。
3. 问：候选人要不要每人记一页？
   建议：在招人的就记，只写代号；只管制度的，不记，首页也不放候选人。
4. 问：每个候选人那一页记这几样，对吗？岗位、做到哪一步、从哪来的、下次跟进、最要紧的事。
   建议：就这五样。做到哪一步只填：看简历、约面试、面过了、发了录用通知、入职了、没通过。
5. 问：制度对不上时谁说了算？
   建议：以最新发文为准；没发文的问人事主管或老板。
