# 结构示例：电商运营

## 分成哪几块

```
wiki/
├─ 商品/   每个商品（或每个链接）记一页
├─ 活动/   每场活动记一页
├─ 复盘/   每次复盘一页（周报、月报、活动复盘）
└─ 规则/   平台规则、发货、售后话术这些，一条一页
```

## 商品卡（`模板/商品卡.md`，放 `wiki/商品/`）

起名：商品简称，比如 `饮水机2.5L-天猫`。同一个商品在几个平台都卖，就一个平台一页。

```markdown
---
类型: 商品
状态: 待核对
更新: "{{date}}"
出处:
  - "[[raw/文件名.扩展名]]"
平台:
店铺:
售价:
在不在卖:
负责人:
最要紧的事:
---
# {{title}}

## 卖点和详情页说法

- （出处）

## 价格和库存

- 日常价、活动价、底价，照哪条规则。（出处）

## 参加过的活动

- [[活动卡的页名]]：卖得怎样。

## 常被问的、常出的毛病

- 没有就写“无”。

## 待补

- 没有就写“无”。
```

各项怎么填：

- 平台：天猫、京东、拼多多、抖音、小红书、独立站……
- 售价：日常价，数字。
- 在不在卖：只用“在卖”“下架了”“在备货”。
- 最要紧的事：现在最要紧的一件事（比如“库存只够两周”）。

## 活动卡（`模板/活动卡.md`，放 `wiki/活动/`）

起名：平台-活动名-年月，比如 `天猫-双11-2026-11`。

```markdown
---
类型: 活动
状态: 待核对
更新: "{{date}}"
出处:
  - "[[raw/文件名.扩展名]]"
平台:
开始:
结束:
做到哪一步:
目标:
负责人:
---
# {{title}}

## 玩法和规则

- 平台要求、报名条件、价格要求。（出处）

## 参加的商品

- [[商品卡的页名]]：活动价。

## 结果

- 卖了多少，跟目标比。没结束就写“没结束”。

## 下次注意

- 没有就写“无”。
```

各项怎么填：

- 开始、结束：日期。
- 做到哪一步：只用“在准备”“进行中”“结束了”。
- 目标：一句话，带数字。

## 复盘页、规则页（知识页）

照 `模板/知识页.md` 写。

- `wiki/复盘/`：`类型` 写“复盘”。一次一页，页头可以加一项 `日期`。写结论和数字的出处，链到商品和活动那几页。
- `wiki/规则/`：`类型` 写“规定”或“流程”。比如 平台价格规则、发货时效、差评怎么回。

## 首页上放什么

- 活动到哪一步了：在准备、进行中的活动。
- 所有商品，看得到在不在卖。
- 最近复盘。
- 要找人拍板的和还缺的、还没整理的原件。

## 定形状时常问

1. 问：你天天打交道的是哪几样？
   建议：商品、活动、每次的复盘；另外是平台规则和发货、售后的规定。
2. 问：最常查、最常被问的 5 件事？
   建议：某个商品现在什么价、库存还有多少、这次活动怎么报名、上次活动卖了多少、平台规则改了什么。
3. 问：每个商品那一页记这几样，对吗？平台、店铺、售价、在不在卖、负责人、最要紧的事。
   建议：就这六样。几个平台都卖的，一个平台一页。
4. 问：每场活动那一页记这几样，对吗？平台、开始、结束、做到哪一步、目标、负责人。
   建议：就这六样。做到哪一步只填：在准备、进行中、结束了。
5. 问：数字对不上时谁说了算？
   建议：价格问运营主管；库存问仓库；活动规则以平台后台为准。
