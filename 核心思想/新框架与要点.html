组织 AI 技能提升实操训练营 · 11 月 7 日至 8 日

实操课新框架与要点

11-04 定的框架，加上当天三次讨论的安排和细节，按上课顺序排，尽量照原话。标待定的还没拍板。

1为什么重做

第一批学员体感：完全是粘贴复制，没有体感，就是跟 AI 聊天，学员页和课程设计有大问题。

  • 每个点都讲得很深很透彻，学员根本不需要。讲的要更少，道理是学员自己在操作中体验出来的。
  • 两天涉及八个技能，不一定一个个教。体量有浅有深。
  • 中台是载体，千万不能喧宾夺主。

2两天做四个项目

周六上午知识库后面每节的产物都存进来
周六下午skill可开发、可维护
周日上午Agent用上前面的 skill，设好身份、边界和目标
周日下午工作流几个 Agent 串起来，看板上看得到真转起来
每一节都用上一节的东西，课不割裂；不跟住，后面跟不上
  • 两天的目标：所有人都能把这四样单独搭起来，知道怎么搭的，也能串起来。回去的时候个人的工作流已经搭起来，能回公司继续用，也知道怎么优化。不是放进黑盒动不了。
  • 知识库放第一：所有产品都能用起来；能同时照顾小白和老手；市面上讲知识库的少。
  • 到工作流时，要让学员看到自己的工作流真正运转起来，并且有产物。

3包怎么给

  • 每块给一个种子：上午一个、下午一个。中间产物和报告文件都不提供，学员自己和 AI 聊出来。
  • 形式：几个文件加提示词，还是封装成四个 skill。待定
  • 用法：学员复制到自己的对话框，里面有几个空，填自己公司的内容，回车，AI 开始问他、跟他聊。
  • 阶段性产物我们先定好。中间怎么聊由 AI 自动引导，不管怎么聊，最后一定引导到产物。
  • 哪几步会出东西（文件、网页）提前告诉学员；聊到一半问一句聊完没有、遇到什么问题；一直聊不完的，要求及时结束。
  • 包是万用型的：课上用课上的版本，回去用自己填的版本；空换一换，日常也能用。看提示词就能看清我们是怎么引导的，回去不用包也能自己聊出来。
  • AI 一次只问一个问题，不夸不安慰；每句要有学员原话或依据，不够写“待补”；上一步的产出贴进下一步。

别丢太多包，学员回去没有包就用不起来，变成现场听着爽、回去不会做。

破题：四个词被说烂了

  • 放 WorkBuddy 技能广场的截图：大家理解的技能是不是这个？点个加号加进去，聊聊天就结束了。
  • 口气别对立。说“你用的不是技能”，台下会杠；打比方说预制菜和自己做的菜，也会被杠“预制菜就一定差吗”。改用提问：进了广场加的那些技能，真的有天天在用吗？用完觉得不顺心了，会调整吗？
  • 要说清的区别：广场上的技能做不出想要的，真实工作场景会出错；同一个方法换到不同人身上，用法不一样；别人断供了，自己也改不动。今天自己搭的能不断迭代。到公司级用，一定要有自己的东西，长在公司内部。
  • 可以插一个对比案例：拿别人的 skill 和用自己做的 skill。
  • 每块准备一个故事，四块四个：先摆“以为的”，再换页摆“真正要学的”。知识库为例：以为的是建一个放公司里，结果东西越来越多管不了，AI 用不上，跑得很慢；真正要学的是一个看得清、用得上的知识库。
  • 最好用视频或图片展示用好之后公司能改造成什么样。

和别家的区别

  • 别人只做单点，我们做架构，能串起来。
  • 不是告诉大家这些能串起来，是这两天真带着串一遍，串的过程中遇到什么问题一起解决。以前的老师只给概念，太虚。
  • 对比用 AB：学了和没学（不学多花几千块踩坑）；公司学前学后；个人学前学后。顺序是全局、对比、细节，先对齐目标。
  • 差异化和“能串起来”谁先谁后。待定

5每一块怎么讲

大架构里每一块再有一个小架构，讲之前先摆出来，让学员有框架感，跟着节奏走。

  1. 是什么：先拉齐，大家以为的可能不太是它。个人的和企业级的分别是什么。
  2. 为什么：放我们真实的案例现身说法，好的差的差多少，做不好会怎样。讲完学员应该有兴趣了，觉得很重要。
  3. 怎么做：发包，复制过去，把括号里换成自己公司的信息，开始和 AI 对话。我们在下面服务。
  4. 做完以后：回去怎么提升、扩展；怎么调用；适用什么范围、什么事做不了；怎么优化迭代；注意事项；对每家企业、每个人意味着什么。
  • 每节开头一个包，结尾一个收拢包，中间穿插案例。大部分时间学员做，共性问题上台讲，个性问题下去帮。
  • 收尾一页 PPT 总结注意事项，是框架性的，不细。细的写成一份文档甩进群里：只给框架和思路，不讲范例；回去照文档走，有问题群里问。相当于每节一个小售后。
  • 讲完每块带一句包含海报上哪几项。PPT 提前做 4 页，反馈好就跳过，没听明白或有质疑就翻出来，可以做 B 版。
  • 案例图放正反两面，最好真实。没有就不放，实在找不到保底自己编，先往下走。

6时间怎么排

  • 每块约 3 小时，讲和练 1 比 3。范例、收拢总结各五到十分钟。
  • 每个下午头 1 小时：上台展示上午的产物。每组抽 1 人，共约 3 人，当场找出逻辑问题马上改，也从里面找共性问题。
  • 每个下午结束再留 1 小时展示，像路演。先找跑得快、跑得好的上台，其他人接着做，现场动态定。
  • 第一天晚课约 2 小时，以答疑为主：回顾当天，学员做的过程中有问题直接上来讲。个人智能体看现场情况讲，大家跑得快就讲，跑得慢就不讲。晚课讲什么，下午四五点心里定好，结束时口播；全都来还是感兴趣的来，看现场状态。
  • 第二天没有晚课。周日下午工作流做完延长一点时间展示，都展示完再用大全景收尾。

7四块各讲什么

知识库

  • 好的差的用我们内部真实的知识库对比：浅的对比丰富的。单点的东西用我们自己的没问题。
  • 展示用起来的知识库长什么样，给数据：入企中只要知识库用起来了，能到多少效果，能处理什么事。
  • 个人知识库和企业级对比讲。权限这些企业级的不演示，简单带过，mamahome 就是范例。企业级要技术，一个人搭不起来；给一个基础架构，像乐高积木，搭得轻快一点。

skill

  • 往企业上走。要同时照顾两种人：很多人已经做过 skill，也有人不知道 skill creator。让做过的人觉得我们讲的和他自己做的不一样，才有兴趣跟着做。
  • 案例：一家客户做了八十多个 skill，截他们的页面。开发得很多，其实用乱了，实际在用的没几个。光做好一次是没用的。
  • 讲到三层：现场做的是可开发，升一维是可维护，再深一层是可进化。“自进化”先削弱，点一下看大家反应，归到可维护里，就是做出来不是不管了。自进化要监控会不会反向变差，堆了大量垃圾上下文，skill 会变差。
  • 先讲怎么做出一个好的 skill，再讲一堆 skill 怎么不断变好、管起来、别互相打架。
  • 现场先问开发过 skill 的举手。没做过的先开发；做过的，老师下去带可维护。备两套：多数没做过就弱化可维护，多数做过就多讲。最后全景图里一定提可维护：后面还有很长的路。
  • 为什么自己建：以前对话式用 AI，让它写一堆提示词，没有沉淀；新任务要重开对话；在旧对话里接着做会污染上下文、跑偏，每次都要改。做成 skill 固化下来，调用时不污染上下文，可复用、可迭代。这是用过的人的真实体会，可以当素材。
  • 一个复杂 skill 有十个功能，改其中一个、其他不受影响，是很深的学问。现场有人用到这么深再讲，没到就先不讲。一种办法是拆成专家团，每个专家只干一件事，改哪个只动哪个。
  • 开发环节可以再举别的案例，比如开源的 skill 进化工具、评测类的。所有案例都要真实。

Agent

  • 先讲大家以为的 Agent（告诉 AI 一句它就搭好了）和真实的 Agent；怎么调用；先搭自己的，再看 Agent team 能拆出什么；用得好和用得差的区别。
  • WorkBuddy 也算 Agent。企业级的不是给员工开一个 WorkBuddy 就结束，是前面的知识库和 skill 都配好，职责很明确。讲 Agent 时把前面的知识库、skill 串一串。
  • skill 是说明书，讲一件事怎么干。Agent 讲身份：它是谁、目标是什么（比如业绩增长 10%）、负什么责、怎么组合用手下的技能。把 Agent 当成技能做，就做坏了。
  • 这一步让学员理解：怎么给它设边界、怎么验收、给它哪部分主动性、怎么审核。具体做什么 Agent 学员自己定，不用一次做很好，身份定义好以后不断磨合调整。
  • 老板觉得自己的判断珍贵，可以教他们做自己的数字分身。
  • 老板最关心 Agent 和工作流两块，这里可以拔高：Agent 好不好用；员工、组织在用 Agent 的效果，老板无从感知；有没有能在企业里复用的 Agent 架构。Agent 算 L2，工作流算 L3。
  • 和技能一样在可维护上下功夫：装了十个技能，要更新，坏的要淘汰，干活不好要提升。讲数字员工那种，不讲通用智能体。Agent team 是工作流的子集。
  • 每人至少做两个 Agent，给下一步工作流用，要用上前面的知识库和 skill。
  • 收不收敛：每人的 skill 不同，Agent 就不同，到工作流很难串。倾向收敛一步，第一个 Agent 大家都做项目经理（看自己的 skill，排日程、排事务），到工作流让项目经理 Agent 管其他几个。既要个性化，又别飞太远。待定
  • 案例只用来让大家知道要做什么，不带着照做；学员从自己的情况出发，按包一步步做出来。
  • 正例：我们做过的一个专家智能体，写出报告给真实用户用过，对话框处理后亮出来。
  • 反例要说清：没想好边界和目标，Agent 就成了纯工具，没权限也没动力，代替不了人。候选：有老板让所有员工开发 Agent，几百个放在一个网页里没人用；某平台建了一百多个 Agent，没用起来，截图要打码。
  • 有人已经用 Agent 帮老板找操盘手，一个人一年一两百万。只用来说明已经有人用到这个程度，我们再拔一层，不当案例：他的卡点在名单从哪来，不在 AI，台下会觉得 AI 没解决卡点。要找的是原来干不了、有了 AI 能干的例子。
  • 现场好多人可能不知道 Agent 是什么。

工作流

  • 完成标准：做出来还得有看板，体现真的转起来了。
  • 为什么要看板：只给老板看文件夹、Markdown、日志，讲不明白协作；放在 WorkBuddy 侧边栏也体现不出谁干了活、谁查了数据、产生多大效果。老板要理解的是协同。
  • 看板比中台轻：看得到每个 Agent 的状态、交接，调了什么工具就推一条线；发一条信息，几个 Agent 都接到调令，互相做了什么都看得见；最后的产物从看板拿。我们提前做好。
  • 做得形象、有趣一点，像在干活的动画。老板看得懂这种，也显出我们年轻、前沿。
  • 专家团后置：前面都让 AI 读专家文件、派子 Agent 当专家；最后提一嘴，用 WorkBuddy 的也可以建成专家团。WorkBuddy 建好的专家团改不了单个专家，得告诉它专家文件在哪，否则整个重建。
  • 工作流比 Agent team 多一截：还要接数据，链条更长。
  • 工具：在 WorkBuddy 里搭专家团，还是统一按 Codex 的做法；Codex 能不能控制多个对话，把产物汇到一处让看板显示。别让学员以为只能用 WorkBuddy、换个软件就不成立。待定，要确认技术可行

8结尾

  • 等式再亮一次，加企业级的超大全景：今天讲的是这一块，后面延伸还很大。可以做成动画，让大家对全景有感知。
  • L1 到 L5 每一层要准备什么，没准备好就上不去，让学员知道现在学的没白费。
  • 企业 AI 化要素：知识库（制度、岗位 SOP、判断、产品信息）；数据（客户、经营、财务、运行日志）；AI 中台（文字、图片、视频、代码等能力，加上 AI 的权限和人的权限）；组织管理和 AI 管理两条线，最好一个人管。

9mamahome：十个人来的那家

  • 母婴电器，工厂加电商；工厂约两三亿，C 端品牌一个多亿、二十多人。来的多半是老板、供应链、产品、营销、财务负责人。
  • 当成课程的标杆案例，效果要炸。各岗位用 AI 做的东西流转到别的岗位审核判断，最后只等老板拍板，像一个微型 FDE。串两个人就够，一个人的 Agent 和另一个人的 Agent 交互；其他人先做单个 Agent。
  • 目的两个：让只来几个人的老板觉得下次要多送人来；让人理解后愿意为后面的服务付费。让大家看到个人跑和企业级跑的区别，L3 现场跑出来，比任何东西都有说服力。
  • 要他们在现场自己做出来、再被串起来，体感才深，不是我们帮他们做。企业级不用太复杂，简单但看得到。
  • 提前准备：多台电脑串联要的环境，服务器、权限、python 这些提前装好；提前联系，摸排电脑和权限，要名单和岗位。第一天晚上单独开小灶。也可以看能不能用飞书练。
  • 数据：倾向用真的；没有就模拟，有表头就行，其余随便填。看哪部分数据不敏感、比较好做。
  • 前面两天重点辅导他们，心里有这个框架；最后一天工作流时呈现效果。
  • 别家问起来：方法都讲，怎么串的也讲；来一两个人的做不了，不算区别对待；想要就付费请我们做。

10现场

  • 虽然叫课，更像工作坊。和大家分享交流，互动实操占绝大部分，不用站在上面很严谨地讲，痛点打痛点。
  • PPT 不上什么字，用视频、图片、流程图。意思清楚就行，不用特别精致。不要 AI 味。
  • 预计卡点（比如网不通、不知道该跟 AI 说公司哪些事），每个备一页，遇到了及时切过去；也可以提前点出来，显出讲师的全局思维。
  • 一人上台讲，其他人都在台下巡场，主动看谁卡住了；换人讲就把台上的替下来。
  • 课后两周线上答疑群；这两天中午、晚课都可以随时找我们。
  • API 不单独讲。mamahome 互联会涉及 MCP，只让学员知道能互联，不讲为什么。金蝶、CRM 这类数据怎么接，是数字化的事，不主动讲，被问了能答。
  • 现场大部分是小白，不要高估。
