实操课新框架与要点

11-04 定的框架，加上当天上午、下午三次讨论的要点，尽量照原话。

1为什么重做

第一批学员体感：完全是粘贴复制，没有体感，就是跟 AI 聊天，学员页和课程设计有大问题。

  • 每个点都讲得很深很透彻，学员根本不需要。讲的要更少，道理是学员自己在操作中体验出来的。
  • 两天涉及八个技能，不一定一个个教。体量有浅有深。
  • 中台是载体，千万不能喧宾夺主。

2两天做四个项目

周六上午知识库搭自己的知识库，后面每节的产物都存进来
周六下午skill做出一个好的，再管好一堆：可开发、可维护
周日上午Agent用上前面的 skill，设好边界和目标，每人至少两个
周日下午工作流几个 Agent 串起来，看板上看得到真转起来
每一节都用上一节的东西，不跟住后面跟不上

怎么带

  • 每节开头一个包，结尾一个收拢包，中间穿插案例。大部分时间学员做，共性问题上台讲，个性问题下去帮。
  • 包里是提示词，留几个空填自己公司的内容，AI 来问学员，最后一定引导到产物。课上用课上版本，回去用自己填的版本。
  • 阶段性产物我们定好；中间产物不提供，是学员和 AI 聊出来的。
  • AI 一次只问一个问题，不夸不安慰；每句要有学员原话或依据，不够写“待补”；上一步的产出贴进下一步。
  • 每块做完，给一份“之后该怎么做”的文档甩进群里：只给框架和注意事项。
  • 每一块同一个路子：先教怎么做出来，再教怎么维护好，往企业级走。

别丢太多包，学员回去没有包就用不起来，变成现场听着爽、回去不会做。

时间怎么排

  • 每块约 3 小时，讲和练 1 比 3；范例、收拢总结各五到十分钟。
  • 每个下午头 1 小时，上台展示上午的产物：每组抽 1 人，共约 3 人，当场改逻辑问题。
  • 每个下午结束再留 1 小时展示，像路演。先找跑得快、跑得好的上台，其他人接着做。
  • 第一天晚课约 2 小时，以答疑为主，回顾当天。第二天没有晚课。
  • 第二天展示完，再收大全景。

3开场破题

  • 四个词别的老师都讲过，开篇先拆开。不对立，用提问：进了技能广场加的那些技能，真的有天天在用吗？
  • 广场上的技能做不出想要的，真实场景会出错，别人断供了自己也改不动；自己搭的能不断迭代。
  • 每块准备一个故事：先摆“以为的”，再换页摆“真正的”。
  • 真正的价值是把四样串起来。别人只做单点，我们这两天真带着串一遍。
  • 对比用学了和没学：多花几千块踩坑；公司、个人学前学后。顺序是全局、对比、细节。
  1. 在 WorkBuddy 技能广场点几个加号，不叫会用技能。
  2. 把录音全打包丢给 AI，不叫做好了上下文。
  3. 做了 80 多个 skill，只有自己会用、没法迭代，常用的还是那几个。
  4. 建个文件夹放着不叫知识库，东西越多越管不了，AI 用不上。

两天的目标：学员能自己把这四样搭起来、拆开、改动，串成闭环。“技能”要破题：比 skill 大，包括交代清楚事情、给对材料、要出处、知道怎么进化、做完谁来核。

4每一块怎么讲

  1. 是什么：简单带过。
  2. 为什么：放案例，做不好会怎样。
  3. 怎么做：发包，带着做。
  4. 做完怎么提升、扩展。
  5. 结尾一页：注意事项、边界、怎么调用、怎么迭代、对企业和个人意味着什么。
  • 每块带一句包含海报上哪几项。备 4 页相关 PPT，反馈好就跳，没听明白就翻出来。
  • 案例图放正反两面，最好真实；没有就不放，实在不行先往下走。

知识库

  • 好的差的用我们真实的东西现身说法：浅的知识库对比丰富的知识库。
  • 个人和企业级对比讲；权限这些企业级的只简单带过，给一个像乐高积木的基础架构。

skill

  • 案例：做了 80 多个，用乱了，实际在用的没几个。光做好一次是没用的。
  • 先讲怎么做出一个好的，再讲一堆 skill 怎么变好、管起来、别打架。
  • 现场做可开发，升一维叫可维护，再深一层是可进化。“自进化”先弱化，点一下看反应。
  • 没做过的先开发；做过的老师下来带可维护。备两套：多数没做过就少讲维护，多数做过就多讲。
  • 为什么自己建：对话式用 AI 会污染上下文、每次重来；做成 skill 固化下来，可复用可迭代。

Agent

  • skill 是说明书，讲一件事怎么干；Agent 讲这个角色是谁、目标是什么、负什么责，怎么组合用技能。
  • 这一步让学员理解：怎么设边界、怎么验收、给它哪部分主动性、怎么审核。
  • WorkBuddy 也算 Agent，但企业用的是知识库和 skill 配好、职责明确的；不是给员工开一个 WorkBuddy 就结束。
  • 老板觉得自己的判断珍贵，可以教做自己的数字分身。
  • 反例：没想好边界和目标，Agent 只是纯工具，没权限也没动力，代替不了人。候选：几百个数字员工放网页里没人用；某平台一百多个 Agent，截图要处理。
  • 正例：我们做过的一个专家智能体，对话框处理后亮出来。
  • 案例只让大家知道要做什么，不带照做；学员从自己的情况出发，按包一步步做出来。

工作流

  • 完成标准：做出来还得有看板，体现真的转起来了。
  • 看板比中台轻：看得到每个 Agent 的状态、交接、调了什么工具，最后产物从看板拿。我们提前做好，做得形象有趣。
  • 工作流算 L3，Agent 算 L2。老板最关心这两块。

5公式和全景

业务结果 = 业务理解 × AI 技能 × 数据和系统 × 分工和流程
  • 开头和结尾都亮出来，括号里是这两天的八项。
  • 结尾放企业级超大全景，可以做成动画：今天讲的是这一块，后面延伸还很大。
  • L1 到 L5 每一层要准备什么，没准备好就上不去，让学员知道现在学的没白费。

6十个人来的那家：mamahome

  • 母婴电器，工厂约两三亿；C 端品牌一个多亿、二十多人。来的多半是老板、供应链、产品、营销、财务负责人。
  • 做标杆：各岗位的 AI 产物流转到别的岗位审核判断，最后只等老板拍板。串两个人、两个任务就够，其他人先做单个 Agent。
  • 要学员在现场自己做出来再被串起来，体感才深。我们提前只铺环境：服务器、权限、python。
  • 提前联系，摸排电脑和权限；第一天晚上单独开小灶；前面重点辅导，第二天呈现效果。
  • 数据有就用真的，没有就模拟，有表头就行。
  • 目的：让只来几个人的老板下次多送人，理解后愿意为后面的服务付费。

7现场

  • 当成给一家公司做内训，像工作坊。PPT 字少，多用流程图、视频和真实投屏，不要 AI 味。
  • 现场大部分是小白，不要高估；好多人不知道 Agent 是什么。
  • 预设卡点，每个备一页 PPT 或一段视频。
  • API 不单独讲；MCP 只让学员知道能互联，问了再答。
  • 一人主讲、拎框架带节奏，一人控场，两人搭内容主体，其他人在下面帮学员。

8还没定的

  1. 包的形式：几个文件加提示词，还是封装成四个 skill。
  2. Agent 这节：在 WorkBuddy 里搭专家团，还是统一按 Codex 的做法只搭一个。WorkBuddy 昨天试了调不了多个专家。
  3. 工作流：每人 Agent 各不相同，难串。倾向收敛，用一个项目经理 Agent 管其他 Agent。
  4. Codex 能不能控制多个对话、把各自产物汇到看板，要确认。
